# Демо-каталог: план seed и очистки

Статус: **план и SQL подготовлены, в базу ничего не записано.** Эти файлы не миграции и не выполняются приложением.
Всё запускается вручную в Supabase → SQL Editor только после вашего подтверждения.

## 1. Что именно создаётся

Шесть демонстрационных товаров. Все значения (названия, цены, вес) демонстрационные, это не реальные позиции магазина.
Значения `metal`, `item_type`, `category` взяты из словаря парсера (`lib/telegram/parser.ts`), поэтому фильтры каталога и
ссылки на главной работают с ними так же, как с настоящими товарами. Бренды, сертификаты, гарантии и отзывы не используются.

Пагинация при размере страницы 12 появится только при 13+ товарах, на 7–12 позициях её не будет видно.

## 2. Как отличаем демо от реальных данных

Демо-строки имеют `telegram_message_id` от −1 до −6. Реальные товары из Telegram имеют положительный id или `null`
(созданы вручную в админке).

Импорт из Telegram (`lib/telegram/import.ts`) этих строк не заденет:
- он ищет существующий товар по `telegram_message_id = <положительный id поста>`, отрицательный id не совпадёт ни с одним постом;
- импорт только вставляет и обновляет, удаления товаров в нём нет;
- cron (`/api/cron/telegram-import`) использует тот же код.

## 3. Фото

Фото берутся из ваших уже существующих файлов `public/images/*.png`: gold-ring, gold-chain, gold-bracelet, silver-earrings,
silver-chain, silver-ring. Они обрезаны до 4:5 и сжаты в WebP (15–67 КБ) в `public/images/demo/`.
Оригиналы не тронуты. В `images` товара записан относительный адрес `/images/demo/….webp`, поэтому Supabase Storage не используется.
Нового файла в бакет `product-images` не загружается.

Что это значит:
- у каждого демо-товара одно фото. Переключение на второе фото при hover и миниатюры галереи для них не появятся;
- фото `test-gold-ring.png` (каблучка с бриллиантом) я не использовал, это то же изображение, что у существующего товара в каталоге;
- эти файлы лежат в репозитории, то есть доступны на любом деплое этой ветки. Если позже решите убрать демо, удалите папку `public/images/demo/`.

## 4. Порядок безопасного запуска

1. **Подтвердите состав** (раздел 6). Я могу поменять названия, цены, статусы, добавить или убрать позиции.
2. Выполните ШАГ 0 из `seed-demo-products.sql` (только чтение): покажет типы колонок `products`. Если `images` не `text[]`,
   `category`/`status` оказались enum с другими значениями, или есть ограничение на отрицательные `telegram_message_id`,
   скрипт упадёт с понятной ошибкой и ничего не запишет, блок атомарный.
3. Выполните ШАГ 1 (`seed-demo-products.sql`). Все 6 строк создаются **неопубликованными** (`is_published = false`),
   то есть на сайте их пока никто не видит.
4. Проверьте их в `/admin` (там они будут как скрытые), затем:
5. **Публикуйте (`publish-demo-products.sql`) только после включения DEMO MODE на публичном деплое.**
   Сейчас форма «Замовити» создаёт настоящую заявку в таблице `orders` и отправляет настоящее уведомление в Telegram.
   Пока DEMO MODE нет, посетитель публичного сайта мог бы оформить заявку на демо-товар.
   Если публичный сайт и есть этот же деплой, порядок такой: DEMO MODE, затем публикация демо.

## 5. Откат

`cleanup-demo-products.sql`: сначала два запроса только на чтение (что удалится и есть ли заявки на демо-товары),
затем закомментированный `delete … where telegram_message_id < 0`. Реальные товары под условие не попадают.
Если на демо-товары уже успели оформить заявки, скрипт покажет их количество, и их судьбу нужно решить отдельно.
Скрыть без удаления можно закомментированным `update … is_published = false` в `publish-demo-products.sql`.

## 6. Что нужно от вас

     и я добавлю позиции, сделаю WebP и расширю seed. Тогда заработают hover со вторым фото и миниатюры галереи.
2. **Значения.** Устраивают ли названия, цены, вес и статусы из таблицы выше? Цены и вес придуманы только для демонстрации.
3. **Порядок.** Подтверждаете, что публикация демо-товаров идёт только после DEMO MODE?
